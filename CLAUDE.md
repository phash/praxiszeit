### E2E-Patterns (Playwright)
- **Mit `TZ=Europe/Berlin` fahren** (`scripts/local-ci.sh` setzt es; lokal `TZ=Europe/Berlin npx playwright test …`) — sonst rechnen die Specs „heute" in UTC (`time-tracking.spec.ts`).
- **`page.goto()` verliert den In-Memory-Access-Token** → Re-Auth per Refresh-Cookie; HTTP-Deployments brauchen `COOKIE_SECURE=false`. Remote: `test.use({ ignoreHTTPSErrors: true })`, `--output=/tmp/...`. Toasts nicht asserten → auf neue Tabellenzeile warten.
- **Locators in `<main>` scopen** (Hilfe-Sidebar dupliziert Texte): `page.locator('main').getByText(...)`.
- **Werktag-Datum:** `weekdayFromNow(n)` aus `helpers/date.helper.ts` statt `daysFromNow(n)` (überspringt Wochenende, Feiertage, 24./31.12.); keine eigene Datumslogik in Specs.
- **`<select>`-Optionen:** `toBeAttached({ timeout: 10000 })` statt `toBeVisible()`.
- **DB-State-Tests:** Unique-Note-Marker (`E2E-${Date.now()}-${random}`) + `filter({ hasText: uniqueNote })` statt `.first()`.
- **Cleanup-Fixtures:** `createTimeEntry`, `createAbsence`, `createChangeRequest`, `createVacationRequest` aus `e2e/fixtures/test-data.fixture.ts` (teardown-DELETE) statt `employeeApi.post(...)`.
- **XLS-Test-Fixtures:** `e2e/test-data/timerec_*.xls` liegen im Repo (regenerierbar via xlwt im Backend-Container).
- **Fehler-Monitoring-Spec braucht einen echten 5xx:** `POST /api/billing/portal` ohne Stripe → 503 „Zahlungsabwicklung nicht konfiguriert" (Betriebszustand). Nie einen Programmfehler als Testgrundlage nehmen. (→ docs/CLAUDE-HISTORIE.md#e2e)
- **Mandantenweite Einstellungen (#451, B9):** Specs, die eine umschalten (`grace-setting.spec.ts`, `vacation_approval_required`, `holiday_state`, `closure_overtime_after_vacation`), liegen in `e2e/tests/tenant-settings/`: Projekt `tenant-settings` mit `dependencies: ['chromium']` UND `workers: 1` (Dateien einzeln nacheinander, sonst Wettlauf); scheitert „chromium", stehen sie als „did not run". Flags vieler Dateien (`shift_planning_enabled`, `vacation_approval_required`) besitzt allein `e2e/global-setup.ts`/`global-teardown.ts` (`OWNED_SETTINGS`) — Specs fassen sie nicht an. Negativtest „Feature aus → 404" in eigene Spec mit Projekt-`dependencies`. Wert im `finally`/`afterEach` zurückschreiben. Allein: `npx playwright test tests/tenant-settings/grace-setting.spec.ts --no-deps`. (→ docs/CLAUDE-HISTORIE.md#e2e)

- **`.env`-Drift:** seit Migration 027 braucht `.env` `APP_DB_USER`, `APP_DB_PASSWORD`, `ENVIRONMENT`, `CORS_ORIGINS` (siehe `.env.example`), sonst `required variable APP_DB_PASSWORD is missing`.
- **Backend-Container ist gebaut** (kein Host-Volume): nach Edits `docker compose cp <host-file> backend:/app/<path>` VOR `pytest`; Prod: `docker compose build backend && docker compose up -d backend`.
- **Frontend `node_modules` ist root-owned** → Host-`npm install` EACCES; `docker run --rm -v $(pwd)/frontend:/app -w /app node:20-alpine sh -c "npm install --silent && ..."`. `npx tsc --noEmit`, `npm run build`, `npm test -- --run` laufen ohne install. Gemischte Owner → als root installieren + im selben Lauf `chown -R <uid>:<gid> node_modules package.json package-lock.json` (auch `tools/`).

Immer die SECHS Postgres-Dateien per `--ignore=` ausschließen wie `scripts/local-ci.sh` (`test_tenant_rls.py`, `test_073_migration_pg.py`, `test_net_hours_parity_pg.py`, `test_reclamp_concurrency.py`, `test_handbuch_seed_pg.py`, `test_concurrency.py`) — sonst `OperationalError`-Kaskade in der geteilten SQLite-Engine. ### Kritische Regeln

#### Allgemein: Backend, Migrationen, Frontend-Konventionen
- Migrationen auf Host erstellen + committen **vor** Container-Rebuild. **Nicht via `python -m alembic`** (cwd-Shadowing durch `alembic/` → `No module named alembic.__main__`) → `python -c "from alembic.config import main; main([...])"` + Retry. Alembic Revision-IDs max. 32 Zeichen (`version_num varchar(32)`).
- Pydantic Response-Schemas: `float` statt `Decimal`.
- **Integer→`Numeric`-Umstellung leakt `Decimal` in ROHE `json.dumps`/`JSONResponse`-Exporte → HTTP 500 für jeden (#383/#408):** alle Rohexport-Flächen des Felds auf `float(x)` prüfen (`grep '"<feld>"' app/services app/routers`; u. a. `lifecycle_service._user_dict`, `auth.py /me/export`). `response_model`/`jsonable_encoder` und Calc (`Decimal(str(...))`) sind safe. SQLite versteckt Numeric-Precision → Round-Trip auf Wegwerf-PG18 + VOLLE `pytest tests/`. (→ docs/CLAUDE-HISTORIE.md#allgemein)
- **Ungültige ID → 422, nicht 500 (#483):** `app/core/db_errors.py` übersetzt NUR SQLSTATE `22P02` (andere wie `22001`/`22003` bleiben 500); Beleg nur auf PG (`test_invalid_uuid_postgres.py`). Logging als WARNING über Logger `app.core.db_errors` mit eingeebneten Steuerzeichen (`message_primary` zitiert Eingaben roh), NICHT nach `error_logs`, nie an den `DBErrorHandler` hängen.
- **SPA-Fallback:** Middleware statt catch-all Route (`@app.get("/{full_path:path}")` → 405 für POST/PUT/DELETE).
- **Daily-Scheduler:** APScheduler in `main.py`, täglich 03:00 Lifecycle-Jobs (Vacation-Audit-Purge 730 Tage, Tenant-Suspend, Tenant-Deletion); im pytest-Mode aus via `PYTEST_CURRENT_TEST`.
- **CR-Approval:** Precondition-Checks VOR Status-Änderung (Race-Condition).
- **clock_out `with_for_update`:** `_get_open_entry()` in `clock_out` MUSS mit Lock laufen (Doppelklick).
- Stunden-Anzeige: `formatHoursHM()` aus `utils/errorMessage.ts` (H:MM, Overflow-safe).
- **ArbZG-Warnungen aus API-Responses:** immer `showArbzgWarnings(toast, response.warnings)` aus `utils/arbzgWarnings.ts`, keine einzelnen `if includes(...)`-Blöcke.
- **Toast-Dauer:** nicht hardcoden — `ToastContext` setzt Defaults (success 3s, error 8s, warning 6s, info 5s).
- Cross-Page Refresh nach Stempeln: `uiStore.notifyStampChange()` → `stampVersion` Effect.
- **§10-Grund im Frontend:** Sonn-/Feiertagsregel allein in `hooks/useSundayOrHoliday.ts` (#491 F4); neue Erfassungsflächen nutzen den Hook statt `getDay() === 0`.

#### nginx, Proxy, Auth-Client
- nginx SPA vs. Static-Dir: `location = /route` VOR `location /`.
- **nginx `/api/`-Proxy: `Host $http_host` (NICHT `$host`) (#dashboard-307, 1.8.6)** in `frontend/nginx.conf` UND `ssl/nginx-ssl.conf` — FastAPI baut den 307-Trailing-Slash-Redirect von Bare-Collection-Routes (`@router.get("/")`, z. B. `/api/dashboard`) absolut aus dem Host-Header; `$host` verliert den Port. Schema via `X-Forwarded-Proto` (uvicorn `--proxy-headers`). Nur Docker. Vite-Dev-Proxy (`frontend/vite.config.ts`) analog `changeOrigin: false` (B6, `src/test/viteDevProxy.test.ts`).
- **nginx: `location ^~ /api/` statt reinem Prefix (#443)** — sonst schlägt die Regex-Location `location ~* \.pdf$` jeden API-Pfad mit Dateiendung (`GET /api/shift-planning/plans/{id}/export.pdf` → 404 vor dem Backend). API-Pfade mit Dateiendung (`.pdf`, `.csv`, `.xlsx`) gegen einen laufenden Docker-nginx testen; Backend-Tests sehen das nie.
- **401-Refresh-Interceptor (`frontend/src/api/client.ts`): `/auth/logout` MUSS ausgeschlossen bleiben** (neben `/auth/login` + `/auth/refresh`) — sonst Endlosschleife logout→refresh→`auth:session-expired`, Connection-Pool satt, 429, Nutzer hängen auf „Lade Dashboard…" (#229). Plus Re-Entrancy-Guard am `auth:session-expired`-Listener in `authStore.ts`. (→ docs/CLAUDE-HISTORIE.md#allgemein)

#### Berechnung Soll/Ist/Saldo
- `get_weekly_hours_for_date()` **immer** pro Tag – nie `user.weekly_hours` direkt.
- **Überstundenausgleich:** Soll bleibt, Ist=0h (NICHT Soll reduzieren!).
- **net_hours Floor:** kann nicht negativ werden (max(0, ...)).
- **Saldo-Stichtag „bis heute" (#313):** `calculation_service.get_soll_cutoff_date(db, user)` = heute, wenn heute ein ausgestempelter `TimeEntry` existiert, sonst gestern. `get_monthly_target/actual/balance(up_to_date=…)`, `get_overtime_account/history(cutoff_date=…)`, `get_ytd_summary(cutoff_date=…)`: `None` = voller Monat. Live-Anzeigen nutzen den Stichtag (`/admin/reports/monthly?soll_basis=bis_heute|monatsende`); **Rechtsbelege ohne cutoff:** `journal_service`, alle Datei-Exporte, Jahresabschluss/`YearCarryover`. `get_overtime_history` bleibt bitgleich zu `get_overtime_account` (`test_history_matches_account_with_cutoff`).

(→ docs/CLAUDE-HISTORIE.md#berechnung)
- **Ist-Gutschrift folgt der Soll-Struktur (`credit_day_weight`, „Fund K", 1.18.0):** SICK/TRAINING senken das Soll nicht, ihre `hours` gehen ins Ist — immer gewichtet mit `calculation_service.credit_day_weight(d, holiday_dates, special_cfg)` (Wochenende/Feiertag 0, Sondertag `special_day_target_factor` — half_day 0,5 / free 0 —, sonst 1,0). #### Vertrags-Snapshot und Wochenstunden-Historie (#415/#431)
- **Jede `WorkingHoursChange`-Zeile ist ein vollständiger VERTRAGS-SNAPSHOT ab `effective_from`** (`weekly_hours`, `use_daily_schedule`, `hours_monday…friday`, `work_days_per_week`, Migration `067`; seit 1.20.0 Blöcke), aufgelöst über `calculation_service.get_schedule_for_date(db, user, datum)` → `Schedule` (`weekly_hours`, `use_daily_schedule`, `day_hours`, `work_days_per_week`); `get_daily_target_for_date(user, datum, schedule)` verlangt ihn als PFLICHTPARAMETER (übersehene Call-Site soll laut scheitern). `user.weekly_hours` = aktueller Wert UND Rückfall vor der ersten Zeile → einziger Schreibweg `POST .../working-hours-changes`; `PUT /api/admin/users/{id}` lehnt alle acht historisierten Felder (`weekly_hours`, `use_daily_schedule`, `work_days_per_week`, `hours_monday…friday`) und `work_blocks` mit 400 ab (`POST /admin/users` darf). **Neuer Soll-Treiber → in den Snapshot (`WorkingHoursChange` + `Schedule`), NIE auf die `User`-Zeile.** Das gilt auch für Kappungsregeln: Arbeitszeit-Blöcke und `pause_minutes` stehen deshalb in derselben Zeile (`working_hours_changes.blocks`); `users.work_blocks` ist nur Rückfall und Spiegel. (→ docs/CLAUDE-HISTORIE.md#snapshot)
- **„Hat dieser Tag ein Soll?" entscheidet der datumsaufgelöste Snapshot, nie ein Live-Feld der User-Zeile:** `calculation_service.is_vacation_billable_day(db, user, d, schedule=None)` (Tagessoll laut Snapshot > 0 in beiden Modi, auch bei `weekly_hours = 0`/Elternzeit) ist die Überspring-Bedingung der Buchungsschleifen; `company_closures._create_closure_absences` gatet deckungsgleich (ruft ihn aus Perf-Gründen nicht selbst). OVERTIME-Gates lesen `use_daily_schedule` aus dem Snapshot. `track_hours=False` (#191) bleibt ungefiltert (Tagessoll 0, tagebasiert trotzdem 1 Tag).
- **Rückrechnung = `calculation_service.retarget_absence_hours(db, user, start, end)`** (DIE eine Stelle, auch Vorschau und Löschen): zieht gespeicherte Abwesenheits-`hours` im Fenster aufs neue Tagessoll (`half_day`/Sondertagsfaktor; nicht `OVERTIME`, nicht `track_hours=False`), wochentagsscharf; gleicht JEDE Zeile im Wirkungsbereich an (Bestand von vor 1.20 → Verkürzung, dokumentiert in CHANGELOG/BERECHNUNGEN TZ-E). Urlaubs**tage** bleiben; Tag ohne Soll zählt nicht als Urlaubsverbrauch, SICK/TRAINING werden dort auf 0 gesetzt (Fund 4). Abgeschlossenes Jahr nur melden. ### Multi-Tenant
- **SaaS-Roadmap:** Meta-Issue [#100](https://github.com/phash/praxiszeit/issues/100) (8 Phasen; Phase 0 in PR #91). On-Prem bleibt single-tenant via `DEPLOYMENT_MODE` (Issue #92).
- **Jede neue Tabelle** braucht `tenant_id` FK + RLS-Policy + Eintrag in Migration.
- **F-026 Tenant-Filter (belt-and-suspenders):** ALLE `db.query(Model).filter(...)` auf tenant-scoped Tabellen tragen zusätzlich zu RLS `Model.tenant_id == current_user.tenant_id` — list, lookup-by-id UND `.delete()`; auch im `calculation_service`, wo `Model.user_id == user.id` eng aussieht. User-Lookup: `_get_user_in_tenant()` in `admin_users.py`. Tests `test_cross_tenant_api.py`, `test_audit_20260731_nachzuege.py`, `test_f026_agy_review.py`. (→ docs/CLAUDE-HISTORIE.md#multitenant)
- **PublicHoliday** wird oft standalone geladen → immer `PublicHoliday.tenant_id == <tid>`; `is_holiday()` immer mit `tenant_id=current_user.tenant_id`.
- Bulk-Deletes: `synchronize_session=False` + expliziter `tenant_id`-Filter.
- **Superadmin-Kontext hebelt RLS aus — dort MUSS jede Query den Tenant selbst filtern:** in jedem `set_superadmin_context`-Pfad (Fehler-Logging `error_log_service.log_error`, Scheduler, Webhooks, Login/Signup) ist der `tenant_id`-Filter Pflicht; `tenant_id IS NULL` (Infrastruktur/anonym) = eigener Topf → `.is_(None)`, nicht `== None`.
- **Neue Tabelle mit FK auf `users.id` → `purge_user()` (admin_users.py, Art. 17) mitpflegen:** passende `ondelete`-Regel, sonst `ForeignKeyViolation` auf PG (SQLite mit FK aus sieht es nie). NOT-NULL-`created_by` vor `db.delete(user)` auf den handelnden Admin umhängen, `user_id`-Daten löschen/`ondelete=CASCADE`. `changed_by` der `time_entry_audit_logs` per ORM + `audit_integrity.compute_row_hash()` umhängen, nie per Bulk-`.update()` (stale `row_hash`).
- **Neue Endpoints:** `set_tenant_context(db, tid)` oder `set_superadmin_context(db)`. **Neue Sessions** (`SessionLocal()`): RLS-Kontext setzen, sonst 0 Rows.
- **`backend/create_handbuch_testdata.py`** ruft `set_superadmin_context(db)` + setzt `tenant_id=TENANT_ID` an User/TimeEntry/Absence/ChangeRequest — Forks müssen beides mitnehmen.
- **DB-User:** App = `praxiszeit_app` (RLS enforced), Migrations = `praxiszeit` (Superuser). **JWT:** `tid` Claim = tenant_id, Middleware validiert gegen DB. Default-Tenant UUID: `00000000-0000-0000-0000-000000000001`.
- **SaaS vs. On-Prem:** `DEPLOYMENT_MODE=onprem|saas` (Default `onprem`), `app/core/deployment.py` → `is_saas()/is_onprem()`. Bootstrap (Default-Tenant, Admin, Holidays) nur `onprem`; `saas` erzeugt Tenants via Signup.
- **JSONB-Spalten:** `JSON().with_variant(JSONB(), "postgresql")` (z. B. `tenants.billing_address`), sonst `can't render element of type JSONB` in SQLite.
- **Billing-Felder:** `tenants` hat `plan | subscription_status | trial_ends_at | seat_limit | stripe_customer_id | stripe_subscription_id | billing_email | company_name | vat_id | country | billing_address`; PATCH `/api/tenant/billing` nur Adresse-Submenge, `plan`/`stripe_*`/`seat_limit` sind webhook/superadmin-owned.

### Claude-Code-Bash-Gotchas
- **`pkill -f <muster>` killt die eigene Shell** → `pgrep -f "[m]uster"` (Klammertrick) und PID gezielt killen.
- **Nativer Install/Update-Test ohne sudo:** Tarball in KURZEN Pfad (Unix-Socket ≤ 107 Zeichen, z. B. `~/.cache/pzn`); `config/praxiszeit.conf` aus `.example` (hoher `port`, ohne `ssl_*`, `cookie_secure = false`); `bin/python/bin/python3 praxiszeit-server.py start`. Update = `rsync -a --delete` von `app/` + `bin/` + `praxiszeit-server.py`. Stoppen per SIGINT.
- **Abgebrochenes `docker compose exec` läuft im Container weiter** → zwei pytest-Läufe teilen `/app/test.db`. Vorher `pgrep -af pytest`, Reste killen, `rm -f /app/test.db`; lange Läufe mit `setsid nohup … &` + Ausgabe in Datei.
- **`grep`-Muster mit führendem `=` frisst ugrep als Option** → `grep -qF -e "===== DONE ====="`.
- **Parallele Workflow-Agenten teilen das Scratchpad** → Hilfsskripte in lane-eigene Unterordner, vor dem Ausführen ansehen.
- **zsh:** `rm -f backend/test.db*` ohne Treffer bricht den ganzen Befehl ab → Dateien explizit nennen. Warten auf pytest: nicht `grep error`, sondern `grep -E "(passed|failed|error).* in [0-9.]+s"`.
- **`$` in Passwort-Hashes nie durch die Shell** (bcrypt-Hash wird zerlegt → Login 401): Hash in Datei, serverseitig `psql … pg_read_file('/pfad')`, im Container `$$…$$`-Quoting.
- `cd` in einem Bash-Aufruf **persistiert** → bei git `git -C <pfad>` oder cwd zurücksetzen.
- `docker compose cp <host-file> <svc>:<container-path>` löst Host-Pfade **relativ zum cwd** auf und braucht den **Service-Namen** (`backend:`, nicht `praxiszeit-backend-1:` — kopiert sonst still nichts). Aus fremdem cwd (z. B. `e2e/` → `lstat e2e/backend/...: no such file`): `docker cp <host-abs-path> praxiszeit-backend-1:/app/<path>`. Verzeichnis: `docker compose cp backend/app backend:/app/` (→ `/app/app`).
- **Fish-Shell:** mehrzeilige `while`/`for … end` scheitern → Einzeiler oder `Monitor`/`run_in_background`.
- **Commit-/PR-/Issue-Texte mit Sonderzeichen** → `git commit -F -` / `gh … --body-file -` mit Heredoc (`<<'EOF'`).
- **`docker compose exec -T …` in einem SSH-`bash -s`-Heredoc frisst den restlichen stdin** → `</dev/null` an jedes `exec -T` oder Skript als Datei + `bash datei.sh`.
- **Pre-Commit-Secret-Scanner** lehnt DB-URL-Literale mit Inline-Passwort ab (auch Tests/Kommentare) → aus Teilen bauen (`s="postgres"+"ql://"; url=s+"u:p@host/db"`), nie `commit --no-verify`.
- **`sudo` nicht via `nohup`/Hintergrund** → `echo "$PW" | sudo -S -v` in derselben SSH-Session, dann foreground. `installer/linux/install.sh` ist interaktiv → Antworten als stdin-Datei (`sudo bash install.sh < antworten.txt`): **Dir zuerst**, dann Praxis/Bundesland (**Nummer**)/Admin-User/Admin-Mail/Passwort ×2/Port/SSL/Confirm (#421/#422); im Update-Modus (`config/praxiszeit.conf` existiert) nur Dir + Confirm. Health-Check → **Exit 1** ohne `healthy` nach 30 s.
- **Backup-Inhaltsvergleich order-UNABHÄNGIG:** je Tabelle `count(*) + md5(string_agg(t::text ORDER BY t::text))`, nie `pg_dump`-Output md5en.
- **Natives Admin-PW für Tests setzen:** `hash_password()` via gebündeltem Python mit DUMMY-`SECRET_KEY` (64 hex), dann per Socket-`psql` `UPDATE users SET password_hash='…', token_version=token_version+1 WHERE username='admin'`.
